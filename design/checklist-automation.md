# Automating the manual release checklist

`validation/release-checklist.xlsx` (generated by `scripts/release_checklist.py`) is 106 manual
steps. This plans an automated enforcer for every one of them, says plainly which cannot have one
and why, and fixes the order of work.

## What "enforced" has to mean here

Three rules, each of them learned the hard way in this repo:

1. **A check that cannot go red is not a gate.** Every enforcer below must be shown to fail when
   the behaviour it guards is broken. Where a check compares two renders, BOTH renders must first
   be asserted non-degenerate — otherwise "these differ" passes trivially when one is blank, which
   is the exact shape of the bug the row exists to catch.
2. **A test that stops existing cannot fail.** The step-to-enforcer mapping lives in
   `scripts/release_checklist.py` beside the step text, and a test asserts every named enforcer
   actually exists. A row claiming coverage it no longer has is worse than a row claiming none.
3. **Automating a row does not delete it.** A machine can check that six colouring methods produce
   six different coherent images; it cannot check that they are *attractive*. Rows that keep a
   human judgement keep their place in the workbook, annotated with what the machine already
   covered so the reviewer knows what is left to look at.

## Classification

| class | meaning | count |
|---|---|---|
| **A** | Fully enforced by a machine check; the manual row becomes a spot-check | 71 |
| **B** | Partly enforced — the effect is checked, the gesture or the aesthetic judgement is not | 26 |
| **C** | Not automatable here; needs a human, a second machine, or a second display | 8 |
| **P** | Process step, not a behaviour | 1 |

Class **B** is not a failure. For "drag to pan", a machine can assert that the pan *action* moves
the view exactly one complex unit per pixel; whether the mouse is wired to that action is a
one-second human check and a screenshot. Splitting it that way tests the part that silently
regresses and leaves the part a person notices instantly.

## New infrastructure

Four pieces, in dependency order.

### 1. `selftest` image-property checks (the big one)

Most of the checklist is "change X, the image should change / stay coherent". `--selftest` already
owns offscreen rendering, a PASS/FAIL check list and 18 goldens, and it is the release gate — so
new checks land there and are counted in `checks N/N`.

Adds a small vocabulary of frame predicates, all computed from decoded RGB (never a file hash —
`--render` embeds metadata):

- `coherent(frame)` — tonal spread and bucket count above a floor. Catches all-black, all-white
  and uniform-flat, which is what rows 48–53 actually mean by "coherent".
- `differs(a, b)` — mean absolute RGB distance above a floor, **after** asserting both coherent.
- `speckle(frame)` — mean absolute difference between neighbouring pixels. The aliasing measure
  from the live-normalisation work; high means salt-and-pepper, low means smooth bands.
- `edge_energy(frame)` — for the anti-aliasing rows.

### 2. `uitest` layout invariants

`--uitest` runs inside the real eframe loop and already captures per-screen screenshots with a
blank-frame check. It gains assertions rather than more screenshots:

- the five regions (menu bar, toolbar, central, right panel, status bar) each exist, have
  non-zero area, lie inside the window, and do not overlap;
- every status-bar readout is populated and parses;
- every `CollapsingHeader` in the control panel opens, allocates height, and closes;
- the rendered complex aspect ratio equals the pixel aspect ratio, at every window size it tries.

That last one is the real content of "no stretching or distortion".

### 3. Action-level tests

Navigation, locations and persistence are pure state transitions on `Viewport` / session data.
They belong in unit tests, not in a GUI harness: undo/redo, goto parsing, bookmark round-trip,
share-string round-trip, `.kfr` import, session save/load.

### 4. `scripts/checklist_coverage.py`

Reads the `enforcer` field added to each step, resolves it against the actual test names in the
tree, and fails if any named enforcer is missing. Emits the coverage summary and adds an
"Automated by" column to the generated workbook.

## Implementation order

Phased so each phase is independently useful and independently verifiable.

1. **Coverage plumbing** — `enforcer` field on each step, `checklist_coverage.py`, the
   "Automated by" column. Nothing else can be trusted to stay true without it.
2. **Selftest image predicates + the colouring/effects/quality matrix** (rows 48–67, 29–30).
   The largest block, and pure offscreen work with no GUI dependency.
3. **The remaining formula goldens** (rows 33–43).
4. **Action-level navigation, locations, persistence** (rows 16–24, 68–75, 100–102).
5. **uitest layout invariants and the aspect-ratio check** (rows 5–14).
6. **Export integrity, including the tile-seam check** (rows 76–80).
7. **Help, settings, accelerated, stability** (rows 87–99, 103–105).

Each phase ends by deliberately breaking the behaviour it guards and confirming the new check
goes red.
